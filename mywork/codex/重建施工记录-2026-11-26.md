## 配置维护

从 `D:\mygame` 执行：

```powershell
python tools/export_data.py
python tools/export_data.py --check
python tests/test_export_data.py
```

导表工具只依赖 Python 3.11 标准库。第一行是字段名，后续行使用字符串、数值或 Excel 布尔值；不接受公式。所有配置校验成功后才写 JSON，各输出文件使用临时文件替换。运行时也先完整校验候选配置，失败则保留原先已加载的数据。

| 源表 | 工作表与用途 |
| --- | --- |
| `tables/cards.xlsx` | `main`：稳定 ID、文案键、职业或专属施放限制、目标、费用、稀有度、奖励资格、消耗与保留；`effects`：基础／升级、效果顺序、类型、数值、段数、仇恨倍率和卡面占位参数。 |
| `tables/characters.xlsx` | `main`：职业、生命、力量、被动、加成、立绘；`starter`：角色起始牌单与数量。 |
| `tables/encounters.xlsx` | `main`：试炼顺序、敌人组合及金币；`enemies`：敌人属性与打断抗性；`intents`：按顺序循环的行动及附加状态。 |
| `tables/battle_rules.xlsx` | `main`：能量、抽牌、上限、仇恨、战后复活等参数；`statuses`：可驱散性、每层效果及衰减。 |
| `tables/texts_zh_cn.xlsx` | `main`：界面、卡牌、角色、状态、错误提示及事件日志的中文文案。 |

导出的每行含 `_source`，错误可追到源表、工作表、行及字段。卡面使用基础值，悬停预览另计当前角色被动、目标缺血等条件。旧规范的“快速治疗”示例由已确认的【治疗术】承接：其基础治疗初值为 14；改到 18 的验收应先使医者本回合【仁心】已消耗，避免额外加成干扰 18／2 治疗、7／1 仇恨的预期。

## 用户手动验收

使用本机 Godot 4.7 可执行文件替换命令中的 `godot`，先打开工程完成资源导入，再执行：

```powershell
godot --headless --path D:\mygame --script res://tests/test_game_data.gd
godot --headless --path D:\mygame --script res://tests/test_battle_rules.gd
godot --headless --path D:\mygame --script res://tests/test_run_flow.gd
```

三组测试分别覆盖加载拒绝与旧数据保留、出牌／预览／治疗取整／同职业归属／死亡与多段／打断／状态批次／驱散，以及战后复活／奖励领取与跳过／最终胜利／失败重开。

从 `scenes/main.tscn` 手动开始试炼，检查下列交互：

1. 首次开局即显示三名角色、敌方意图、5 张手牌和 3 点能量。
2. 攻击牌点友方被拒绝；自施护盾必须点击“施放”；取消不耗费资源。
3. 对治疗牌悬停缺血目标，核对预览、血量变化与日志；急救遇多种负面状态需要先选择。
4. 选牌后结束回合，再点目标不得误打下一回合手牌；演出中不能出牌或结束回合。
5. 胜利后领取或跳过只推进一次；继续战斗后存活角色血量延续，阵亡角色自动恢复；试炼完成和失败均可重新开始。
6. 手动缩放窗口，查看单位信息、牌堆弹窗和横向滚动手牌；窗口布局与中文显示仍需实机确认。
